## Family critic: the antialiased centre-line residual

A family critic found one low-severity gap in the core, Flow, Prism and Lit. With antialiasing, a few silhouette pixels near a centre line of the render still take the wrong orientation sign: up to 8 per row of twelve renders. Liquid Glass Lit's form (e), a centroid-sampled position, removes most of those in the usual raster, but it needs a `centroid` vertex output that no TouchDesigner build has run. The critic's fix: keep it a family open question until a native check shows whether the residual is visible, and if it is, try a centroid-qualified vertex output for the projected position in one member first. This round changed no shader, preset, uniform expression or capture. Every image result below is a WebGL preview (Chromium SwiftShader), not a TouchDesigner render. Nothing ran in TouchDesigner. Scratch runs: `agents/centre-line-residual` in the session scratchpad.

**Comparing the two centre-line forms (G2).** On paper they are one algorithm: compare the projected position with the raster position, and on an odd-size centre line take the sign of the projected position's screen derivative where 1/w changes by less than 10% to the next pixel. This study's `screenSign()` returns the raster's direction and `cam.viewSign` applies the projection's sign afterwards; the core's multiplies it inside, and computes its projected point as `proj x (cam x world)` rather than `viewProj x world`. A scratch copy of this shader with the core's function pasted in literally gave the same counts as this study's own on all twelve rows of the family's survey, value for value. Neither is measurably better, so this study keeps its lines, which the core and Lit now share.

**How the demo and the presets map (G1).** The rule says Object size 1 is a radius of 1.45. This demo torus is a little wider than the core's (half its largest side is 1.5, not 1.45), but its Geometry COMP flattens it to 0.6 in depth. Fit counts a non-uniform scale as its average, the cube root of 0.6 (0.843), so it measures 1.5 x 0.843 = 1.265. Its presets were tuned with Object size 1 meaning that torus. Three routes were weighed: scale the demo and its camera so it fits to 1 (the same image, but more nodes and the preview's default scene change), keep Object size 1 as the default (then pressing Fit on the demo changes the look), or keep the demo, make its fitted size 0.872517 the default, and map the presets once. The third changes the least. The six prism looks are mapped; the six core looks keep the core's values, because the rule's point is that a core preset means the same object size in every member. Measured on the demo (torus over the checkerboard, time 2, each tree at its defaults): with the film off, the prism looks differ from c94e849 by at most 10/255 on at most 4 pixels over 8 (3-decimal rounding). The film keeps the family's 2.5 swirls per Object size, which here is 0.9667 times the old count on the object. So Spectral Prism (Iridescence 0.3) differs by 73/255 on 5,018 pixels; the others by less.

## Numerics

- **Finite output.** 200 renders without and 200 with the back-face pass (5 shapes x 5 extreme settings x 8 stages), plus 24 on meshes without normals, read back as 32-bit floats: no NaN or infinity. The largest value, 1492, is the Thickness teaching stage at Thickness 0 with the back-face pass (measured path / 0.001). It is a display value; the final image never divides by Thickness.
- **Guards.** `leaveGlass()` clamps the incidence cosine, so a far normal that faces the ray counts as grazing (trapped) rather than producing a reflected direction. Fresnel denominators have a floor of 1e-6; at IOR 1 the numerators are exactly 0. The ball estimate's normal is unit length by construction; the sheet path's cosine has a floor of 0.2. `projectOffset()` keeps every projected point at least half as far from the camera as its reference point (instrumented test, Scene depth up to 50, camera 1.8 to 5 units away). The exit march has at most four corrections, a clamped step rate and a clamped distance. The per-slice re-read's path scale is clamped to 0.5 to 2.
- **Continuity.** No per-pixel noise source (unit test) and no grain in a frosted image (preview test). The trapped share reaches 1 smoothly (monotonic in the TIR test). The Exit tilt blend, including the path, is continuous at 0. The near-camera pull-back is continuous where it starts. The bounce blend uses smoothstep. Mip levels follow each lookup's footprint, so strongly shrunk views blur instead of aliasing; the level is constant over each 2 x 2 pixel block, as in any hardware mip selection. `backSample()` uses bilinear weights over valid texels, so it changes smoothly except at the silhouette of the back-face pass, where it falls back.
- **Derivatives.** `dFdx`/`dFdy` appear only at the top of `main()` (faceted normal) and in `footprintLod()`, called from a loop whose count and branches depend on uniforms only (unit test). Since the family sync the screen orientation needs none.
- **Sensitivity.** Near the critical angle the image is very sensitive to the normal (see the first finding). Wobble or coarse meshes will make trapped bands shimmer. This is physical, but worth knowing.

## Geometry and conventions

- Normals go through `TDDeformNorm`; the liquid ripples use `uTDMats[].worldForNormals`, as in the core study. Both passes use faceted normals from screen derivatives when the SOP has none (tested with N = 0 in the preview; what `TDNormal()` returns then is a native check).
- All 3D points reach the screen as offsets from `screenUV()`, projected with `uTDMats[].proj * uTDMats[].cam`. An unbent ray lands on its own pixel whatever the build's screen convention. The offsets' signs follow the screen orientation measured per pixel (since the family sync by comparing the pixel's projected position with its raster position); Flip V flips the base UV and the vertical offsets together.
- Only the 2D render mode and one camera per Render TOP are supported; Quad Reproject cameras are untested (README "Not supported"). The vertex shader has TouchDesigner's documented picking branch.
- Eye distance is straight-line for perspective cameras and along the view axis for orthographic ones, in both passes. `ior1_invisible_orthographic` passes.
- `render_back` is RGBA 32-bit float, one colour buffer, Anti-Alias 1x (no averaging of distances), background 0, Pre-Multiply off; `material_back` has blending and Post-Mult off and culls front faces. It stores minus the eye distance, so any non-negative background reads as empty. It is read with `texelFetch`, so no filtering of 32-bit floats is assumed. Its Geometry follows every object Glass geometry lists.
- Output is premultiplied alpha with One / One Minus Source Alpha blending on `material`, as in the core study.
