## Geometry and conventions

- Normals go through `TDDeformNorm`, so object transforms, non-uniform scale and instancing follow TouchDesigner's own normal handling. The liquid ripples use `uTDMats[].worldForNormals`, which excludes instance transforms, multiplied by the object's scale so Wobble does not depend on it (tested in the preview at scale 0.1, 1 and 10). Since the family close the ripple and film lookups are also multiplied by that scale (`worldScale()`), so Object size is the object's world size for the patterns as for the lengths (the family rule).
- Geometry without normals should fall back to faceted normals from screen derivatives: the vertex stage keeps a missing normal at exactly zero, and the derivative test is relative to the pixel size (tested in the preview with the normal attribute removed). What TouchDesigner's `TDNormal()` returns without an N attribute is undocumented; native check pending.
- Screen UV comes from `gl_FragCoord` and `uTDGeneral.viewport`, which follow TouchDesigner's texture rows. The screen orientation is measured per pixel; on the centre lines of an odd-sized render the projected position's screen derivative breaks the tie (family close G2). A Flip V toggle exists in case a build disagrees; it should stay off.
- Camera position comes from `uTDMats[].camInverse[3]`. The camera index is passed from the vertex stage, because `TDCameraIndex()` is vertex-only. Orthographic cameras are handled, including the back-face thickness, which uses depth along the parallel rays (tested in the preview since round 2).
- Output is premultiplied alpha, with One / One Minus Source Alpha blending on `material`. The back-face material has blending off because its alpha carries a distance.

## Audit round 3

A critic agent re-read the study after round 2 and reported two findings with reproductions; a verifier confirmed both. This round re-checked each one before changing anything, with Python against the real `presets.py`, `native.py` and `study.json`, and with the preview:
