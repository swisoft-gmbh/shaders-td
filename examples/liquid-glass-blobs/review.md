## Geometry and conventions (review criteria: material route)

- **Geometry selection:** the blobs exist only inside `blobs_geo`. The demo Render TOPs list their objects explicitly (`blobs_geo demo_ring` and `demo_ring`), never a wildcard.
- **Transforms:** the vertex stage sends `TDDeform` of the object's origin and axes, so Geometry COMP, parent and instance transforms all apply. Normals use the inverse transpose. Skinned deforms are not affine and are not supported; a box never needs them.
- **Camera:** each pixel's ray comes from `uTDMats[].camProjInverse` (the point where the pixel's ray crosses the near plane) and the box point `vWorldPos`, so any projective camera works and the near plane clips. The camera index travels from the vertex stage because `TDCameraIndex()` is vertex-only. Orthographic and blended projections are tested in the preview.
- **Depth:** `gl_FragDepth = (camProj * P).z / w`, relying on the documented 0..1 ("Vulkan style") depth range of `uTDMats[].proj`. It is not the full `TDWorldToProj` path, which is vertex-only. Fisheye, quad reprojection and picking adjustments are therefore not applied to the blob surface; the vertex stage writes TouchDesigner's default pick values for the box.
- **Faces:** back faces only (Cull Face = Front Faces), one fragment per pixel for the convex box, so the camera may be inside the box.
- **Alpha:** premultiplied output with One / One Minus Source Alpha. Post-multiply and the Render TOPs' pre-multiply are set explicitly off, following the core's round-1 review.
- **Unconnected samplers** point at `blank`, a 4 x 4 transparent Constant TOP (core round-1 fix). Expressions call `.eval()` (core round-1 fix). Flip V flips only the screen UV (core round-1 fix).

## Numerics

- Smooth minimum: explicit zero-width branch (k < 1e-4 returns min). Its slope never exceeds 1, so steps stay safe. Ripples add a known slope that `stepScale()` compensates for.
- Bounded loops: every loop has a constant upper bound (256 march steps, 12 blobs, 6 droplets, 32 colour samples, 8 blur taps).
- Divisions: the slab test guards zero direction components; Newton steps clamp the slope; `safeDirection()` falls back on zero vectors; the clip-space w of a point in front of the camera is positive.
- Finite outputs: the finite-check stage and a float readback of the final image found no NaN or infinite values across merge widths 0 to 1, an extreme layout, coincident centres, blobs cut by the box walls, a zero light direction and a light along an orthographic view. The finite-check stage tests float bits; a NaN tint density turns it red (positive control).

## Remaining risks (for the native run)

1. **Depth convention.** If a build or a camera mode does not use the documented 0..1 depth for `proj`, the blobs sort wrongly against other geometry. Check with the `depth` experiment: the ring must pass in front and behind.
2. **CHOP to TOP and DAT to CHOP parameters** (`dataformat`, `layout`, `format`, `output`, `firstrow`, `firstcolumn`) come from the documentation, not from a running build. These nodes are demo-only and lenient.
3. **Cost.** Every box pixel marches, and writing depth disables early depth rejection. Large boxes on screen at high resolution may be slow; no timing exists yet.
4. **Opacity below 1 and zero-wiring mode** with depth writing hide objects drawn later behind the blobs. `blobs_geo` has Draw Priority -1 (set leniently); the Transparency page contradicts itself on which way Draw Priority sorts, so check it natively.
5. **The preview's TouchDesigner stand-ins** (camera FOV, instancing, the layout texture, fog) are models of the documented behaviour, not the host.
6. **Fog and picking** follow the docs and TouchDesigner-style shaders in glslang's tests, not a native run. A native compile error in the pick render would only affect Render Pick.
7. **The finite check on macOS** may still be optimised by fast math, even with the bit test. Run its positive control natively (validation.json).
