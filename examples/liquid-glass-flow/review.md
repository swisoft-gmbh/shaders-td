## Geometry and conventions

- Field and displacement are computed in the SOP's object space, in units of Object size from Flow centre. The Geometry COMP's transform, non-uniform scale and instance transforms apply afterwards through `TDDeform`; normals through `TDDeformNorm`.
- Crack-free mode moves each point along `normalize(position - centre)` by a field of the position only, so vertices that share a position always move together; within 0.05 object sizes of the centre the direction fades to zero. Normal mode uses the vertex normal and treats the surface as flat when rebuilding the normal (up to 10 degrees off on the demo torus at preset amplitudes).
- Normals are rebuilt with central differences along two tangents (`cross(J t1, J t2)`); the result is kept on the side of the original normal. The rest normal is kept only where the moved patch is squeezed to under a thousandth of its rest area (2e)^2, which happens where the surface folds through itself, or where the result is NaN (`flowNormal()`, liquid_flow.vert:185). At Amplitude 0 the vertex stage does exactly what the core's does.
- Gravity is converted from world to object space with `mat3(uTDMats[].worldInverse)`, then by the inverse of `TDInstanceMat3()` (skipped if singular), so instances sag world-down too.
- Field time: `uFlow.w` is flow time from `presets.flow_time()` (the core's `advance()` since the family sync; `clock()` before), wrapped at 25600 s. The noise lattice repeats every 256 cells and `driftNoise()` folds each drift into one repeat, adding whole cells to the lattice index and only the fraction to the position, so no large float meets the 0.001 nudge.
- A zero-length `TDNormal()` is treated as "no normals": the point moves away from the centre and the pixel stage builds faceted normals from screen derivatives. Derivative's page does not say what `TDNormal()` returns for a SOP without normals; this is an assumption to check natively.
- The pixel stage is the core's (premultiplied alpha, One / One Minus Source Alpha, back-face pass with distance in alpha). `material_back` shares every flow uniform, so the inner surface moves identically.

**Why two sizes, and why the default is 0.69.** The motion happens in the SOP's space, before `TDDeform`, so it needs a size in SOP units. The glass is seen in the world, and the family rule measures it there. One control for both cannot follow the rule without the motion's unit depending on the reference radius and the COMP's scale. So Flow size took the motion and Object size the glass. The default Object size is what Fit sets on the default demo object, the radius-1 sphere: 1 / 1.45. The alternative, the core's default 1, keeps the old demo look, but then pressing Fit on the demo changes it. `co-design.json` records this as an inferred choice; the user's decision is LOOK-F1 there ([Look decisions](#look-decisions)). A demo sphere of radius 1.45, first offered as a way to keep the old look, does not keep it: measured, it renders today's look.
